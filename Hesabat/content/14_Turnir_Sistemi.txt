# 14. Turnir Sistemi (Arena Tournaments)

## 1. Giriş və Məqsəd

Fərdi (1v1) oyunlardan əlavə, "Grandmaster" tətbiqi istifadəçilərə **Arena tipli turnirlər** təşkil etmək və onlara qoşulmaq imkanı verir. Arena formatı — Lichess platformasının populyarlaşdırdığı bir formatdır: bütün iştirakçılar EYNİ VAXT ARALIĞINDA (məsələn, 30 dəqiqə) İSTƏNİLƏN SAYDA oyun oynayır, hər qələbə/bərabərlik xal qazandırır, və turnir sonunda ƏN ÇOX XALI TOPLAYAN QALİB OLUR. Bu sənəd turnirin data modelini, idarəetmə xidmətini (`TournamentService`) və UI ekranlarını əhatə edir.

**Fayllar:**
- `lib/core/models/tournament_model.dart`
- `lib/core/services/tournament_service.dart`
- `lib/features/tournaments/screens/tournament_list_screen.dart`
- `lib/features/tournaments/screens/create_tournament_screen.dart`
- `lib/features/tournaments/screens/arena_lobby_screen.dart`

## 2. İstifadə Olunan Texnologiyalar

- **`cloud_firestore`** — turnir metaməlumatları (`tournaments` kolleksiyası) və iştirakçı sənədləri (`tournaments/{id}/participants/{uid}` alt-kolleksiyası).
- **`firebase_database` (Realtime Database)** — Arena FAZASINDA AKTİV OYUNÇU CÜTLƏŞDİRMƏSİ (pairing) üçün sıra (queue) sistemi: `arenas/{tournamentId}/queue/{uid}`.
- **Firestore Tranzaksiyaları (Transactions)** — xal yeniləmələrinin (`recordArenaResult`) və turnirin bitirilməsinin (`finishArena`) ATOMIK VƏ İDEMPOTENT olmasını təmin etmək üçün.
- **`Timer.periodic`** — Arena Lobi ekranında geri sayım (countdown) və avtomatik bitirmə yoxlaması üçün.
- **Dart enum-lar** — `TournamentStatus {waiting, active, finished}` turnirin həyat dövrü mərhələlərini təmsil edir.

## 3. TournamentModel: Data Strukturu

> class TournamentModel {
>   final String id;
>   final String name;
>   final String description;
>   final String gameType;            // 'chess' | 'checkers' | 'domino'
>   final TournamentStatus status;
>   final String creatorUid;
>   final String creatorUsername;
>   final int maxPlayers;              // 8 | 16 | 32
>   final String timeControlLabel;     // "5+0", "3+2" və s.
>   final int timeSeconds;
>   final int incrementSeconds;
>   final int durationMinutes;         // Arena müddəti
>   final DateTime? endsAt;
>   final DateTime createdAt;
>   final int participantCount;
>
>   bool get isActive   => status == TournamentStatus.active;
>   bool get isFinished => status == TournamentStatus.finished;
>   bool get isWaiting  => status == TournamentStatus.waiting;
>
>   static (int, int) parseTCLabel(String label) {
>     final parts = label.split('+');
>     return (int.parse(parts[0]) * 60, int.parse(parts[1]));
>   }
> }

`parseTCLabel()` statik metodu — istifadəçi-dostu format olan `"5+0"` (5 dəqiqə + 0 saniyə artım) sətrini, daxili hesablamalar üçün lazım olan `(timeSeconds=300, incrementSeconds=0)` formatına çevirir. Bu, UI-da göstərilən format ilə oyun mühərrikinin gözlədiyi format arasındakı "körpüdür".

## 4. ArenaParticipant: İştirakçı Modeli

> class ArenaParticipant {
>   final String uid;
>   final String username;
>   final int rating;
>   final double score;     // qələbə=2, bərabərlik=1, məğlubiyyət=0
>   final int wins;
>   final int draws;
>   final int losses;
>   final int gamesPlayed;
>   final DateTime joinedAt;
> }

Diqqət ediləsi məqam: `score` sahəsi STANDART şahmat xal sistemindən (qələbə=1, bərabərlik=0.5) FƏRQLİ olaraq, **qələbə=2, bərabərlik=1, məğlubiyyət=0** sxemi istifadə edir. Bu, Arena tipli turnirlərdə YAYĞIN olan bir konvensiyadır (Lichess Arena də buna bənzər bir sistemdən istifadə edir) — onun üstünlüyü ondan ibarətdir ki, BÜTÜN xallar TAM ƏDƏD (integer-ə bənzər `double`) olur və UI-da "12 xal" kimi sadə göstərilir, "6.0 xal" kimi onluq kəsr qarışıqlığı yaranmır.

## 5. TournamentService: Əsas Metodlar

#### 5.1. createTournament() və joinTournament()

> Future<String> createTournament(TournamentModel tournament) async {
>   final ref = await _firestore.collection('tournaments').add(tournament.toMap());
>   await joinTournament(
>     tournamentId: ref.id,
>     uid: tournament.creatorUid,
>     username: tournament.creatorUsername,
>     rating: ...,
>   );
>   return ref.id;
> }
>
> Future<void> joinTournament({required String tournamentId, required String uid,
>     required String username, required int rating}) async {
>   await _firestore
>     .collection('tournaments').doc(tournamentId)
>     .collection('participants').doc(uid)
>     .set(ArenaParticipant(uid: uid, username: username, rating: rating,
>          score: 0, wins: 0, draws: 0, losses: 0, gamesPlayed: 0,
>          joinedAt: DateTime.now()).toMap());
>   await _firestore.collection('tournaments').doc(tournamentId)
>     .update({'participantCount': FieldValue.increment(1)});
> }

Turnir yaradıldıqda, YARADAN İSTİFADƏÇİ AVTOMATIK OLARAQ İLK İŞTİRAKÇI kimi qoşulur — istifadəçinin əlavə bir "Qoşul" düyməsinə basmasına EHTİYAC QALMIR.

#### 5.2. startArena() — Turniri Başlatmaq

> Future<void> startArena(String tournamentId, int durationMinutes) async {
>   final endsAt = DateTime.now().add(Duration(minutes: durationMinutes));
>   await _firestore.collection('tournaments').doc(tournamentId).update({
>     'status': 'active',
>     'endsAt': Timestamp.fromDate(endsAt),
>   });
> }

Status `waiting`-dən `active`-ə keçir və `endsAt` ZAMAN DAMĞASI YAZILIR — bu, BÜTÜN İŞTİRAKÇILARIN CİHAZLARINDA EYNİ "bitmə anını" sinxron şəkildə göstərməsini təmin edir (server vaxtına əsaslanır, klient saatına deyil).

#### 5.3. finishArena() — İdempotent Bitirmə

> Future<void> finishArena(String tournamentId) async {
>   await _firestore.runTransaction((txn) async {
>     final doc = await txn.get(_firestore.collection('tournaments').doc(tournamentId));
>     if (doc.data()?['status'] == 'finished') return;  // artıq bitib
>     txn.update(doc.reference, {'status': 'finished'});
>   });
> }

Bu metodun TRANZAKSİYA içində icra edilməsi və "artıq bitibsə heç nə etmə" yoxlaması — onu **idempotent** edir, yəni eyni anda BİRDƏN ÇOX İSTİFADƏÇİNİN CİHAZI eyni `finishArena()` çağırışını etsə belə (məsələn, hamısının taymeri eyni anda 0-a çatdıqda), nəticə DƏYİŞMİR və status İKİ DƏFƏ "finished"-ə yazılmağa çalışıldığında xəta baş vermir.

#### 5.4. recordArenaResult() — Xalların Yenilənməsi

> Future<void> recordArenaResult({
>   required String tournamentId,
>   required String whiteUid,
>   required String blackUid,
>   String? winnerUid,
>   bool isDraw = false,
> }) async {
>   final batch = _firestore.batch();
>   for (final uid in [whiteUid, blackUid]) {
>     final isWinner = uid == winnerUid;
>     final scoreDelta = isDraw ? 1.0 : (isWinner ? 2.0 : 0.0);
>     final ref = _firestore.collection('tournaments').doc(tournamentId)
>                            .collection('participants').doc(uid);
>     batch.update(ref, {
>       'score': FieldValue.increment(scoreDelta),
>       'gamesPlayed': FieldValue.increment(1),
>       if (isDraw) 'draws': FieldValue.increment(1)
>       else if (isWinner) 'wins': FieldValue.increment(1)
>       else 'losses': FieldValue.increment(1),
>     });
>   }
>   await batch.commit();
> }

`FieldValue.increment()` istifadəsi VACİBDİR — bu, Firestore-un SERVER TƏRƏFİNDƏ atomik artırma əməliyyatıdır, yəni eyni anda ON-LARLA OYUNUN NƏTİCƏSİ YAZILSA BELƏ, "race condition" (yarış vəziyyəti) baş vermir və heç bir xal "itmir".

## 6. Turnirin Həyat Dövrü (Lifecycle)

#### Mərhələ 1: Gözləmə (Waiting)
- İstifadəçi `CreateTournamentScreen`-də turnir yaradır → status=`waiting`.
- Yaradan avtomatik qoşulur, digər istifadəçilər `TournamentListScreen`-dən tapıb qoşula bilər.
- Hər qoşulma `tournaments/{id}/participants/{uid}` alt-sənədini yaradır və `participantCount` artırılır.

#### Mərhələ 2: Aktiv (Active) — Arena Pairing
- Yaradan `startArena()` çağırır → status=`active`, `endsAt` təyin olunur.
- İştirakçılar "Hazıram" (Ready) düyməsinə basaraq Realtime Database-də `arenas/{tournamentId}/queue/{uid}` sırasına qoşulur.
- **Cütləşdirmə (Pairing) Tranzaksiyası:** Sırada İKİ İSTİFADƏÇİ olduqda, bir TRANZAKSİYA onları "tutur" (claim) və aralarında yeni bir oyun (`GameModel`, `mode: online`, vaxt nəzarəti turnirin TC-sinə uyğun) yaradır, hər iki istifadəçini sıradan çıxarır.
- **30 Saniyəlik Bot-Fallback:** Əgər istifadəçi 30 saniyə ərzində CÜTLƏŞDİRİLMƏYİBSƏ (məsələn, tək qalıb), sistem ona AVTOMATIK OLARAQ BOT RƏQİB TƏYİN EDİR ki, oyunçu "boş gözləməsin" və turnirdə davamlı iştirak edə bilsin.
- Hər bitən oyundan sonra `recordArenaResult()` çağırılır.

#### Mərhələ 3: Bitmiş (Finished)
- `endsAt` vaxtı keçdikdə, HƏR İŞTİRAKÇININ CİHAZINDAKI `Timer.periodic` bunu aşkarlayır və `_checkAndFinish()` vasitəsilə `finishArena()` çağırılır (idempotent olduğu üçün təhlükəsizdir).
- Yekun sıralama `watchParticipants()` vasitəsilə `score` görə AZALAN sırada göstərilir, qalib(lər) podium formatında vurğulanır.

## 7. UI Ekranları

#### 7.1. TournamentListScreen
- **Filtr Tabları:** "Hamısı" / "Gözləyən" / "Canlı" / "Bitmiş" — `TournamentStatus` enuminə uyğun.
- **Oyun Növü Keçidi:** İstifadəçi şahmat/dama/domino turnirləri arasında keçə bilər (`activeGameProvider`-dən asılı).
- `watchTournaments()` — ən son 50 turniri REAL-VAXT göstərir.
- Yaradan "+" düyməsi `CreateTournamentScreen`-ə yönləndirir.

#### 7.2. CreateTournamentScreen
Form sahələri:
- **Ad** (məcburi) və **Təsvir** (ixtiyari).
- **Oyun Növü** — cari aktiv oyun növündən (`activeGameProvider`) avtomatik götürülür.
- **Vaxt Nəzarəti** — açılan siyahı: `['1+0', '2+1', '3+0', '3+2', '5+0', '5+3', '10+0', '10+5']`.
- **Müddət** (dəqiqə) — `[15, 30, 45, 60]`.
- **Maksimum Oyunçu** — `[8, 16, 32]`.

"Yarat" düyməsi: validasiyadan sonra `parseTCLabel()` ilə vaxt nəzarətini ayrışdırır, `TournamentModel(status: waiting)` qurur, `createTournament()` çağırır və yaradılan turnirin lobi ekranına (`/home/tournaments/{id}`) yönləndirir.

#### 7.3. ArenaLobbyScreen
`ConsumerStatefulWidget` olaraq, BEŞ DAXİLİ VƏZİYYƏT DƏYİŞƏNİ saxlayır: `_tournament`, `_participants`, `_isParticipant`, `_isReady`, `_isPairing`, `_timeRemaining`, `_queueSeconds`. Eyni zamanda DÖRD STREAM-Ə ABUNƏ olur:
- `watchTournament()` — turnirin status/endsAt yenilənmələri.
- `watchParticipants()` — sıralanmış iştirakçı siyahısı (xal görə azalan).
- `watchMyArenaPairing()` — istifadəçi üçün YENİ CÜTLƏŞDİRİLMİŞ OYUN yaradıldıqda bildiriş.
- `watchArenaQueue()` — sırada neçə nəfər gözlədiyini göstərir.

`Timer.periodic` hər saniyə `_timeRemaining`-i yeniləyir və `endsAt`-a çatdıqda `_checkAndFinish()` çağırır.

## 8. Nəticə

Turnir sistemi, "Grandmaster" tətbiqinin SOSIAL VƏ RƏQABƏTLİ qatını gücləndirən, Firestore (davamlı, struktur saxlama) və Realtime Database-in (aşağı-gecikməli, müvəqqəti sıra idarəetməsi) GÜCLÜ TƏRƏFLƏRİNİ BİRGƏ İSTİFADƏ EDƏN hibrid bir memarlıqdır. Tranzaksiya əsaslı, idempotent əməliyyatlar (`finishArena`, `recordArenaResult`) çoxistifadəçili mühitdə MƏLUMAT BÜTÖVLÜYÜNÜ qoruyur, 30 saniyəlik bot-fallback mexanizmi isə istifadəçi təcrübəsinin HEÇ VAXT "tıxanmamasını" təmin edir.
